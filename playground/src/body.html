Rate limiting you can watch work.

RateGate is an open-source, distributed rate limiter for Go: token bucket, sliding window and adaptive AIMD policies behind one REST and gRPC API, backed by memory or Redis. The playground runs line-by-line ports of the server's own algorithms. Tune a policy, flood it, and see every request admitted or turned away.

        Algorithms
        
Three ways to say no. Pick by what you need to guarantee.

        
All three answer the same question, "may this key proceed?", but they differ in what they promise over time, what each key costs in memory, and which stores can run them.

      

      

        

          

            
              

                Property
                Token bucket
                Sliding window
                Adaptive (AIMD)
              

            
            
              

                Best for
                API quotas that should tolerate short bursts
                Hard limits such as "N per minute"
                Backends whose capacity you cannot predict
              

              

                Bursts
                Up to limit at once; a new key starts full
                Up to limit inside one window
                Up to the effective limit per window
              

              

                Long-run promise
                An average of refill_per_second
                No more than limit per window*
                Effective limit inside [floor, 4 × floor]

                About 48 B
                About 960 B in memory (60 sub-buckets)
                A handful of fields, no ring
              

              

                Check cost
                40 ns/op, 0 allocations
                153 ns/op, 0 allocations
                Not in the benchmark suite yet
              

              

                Stores
                memory, Redis, Redis Cluster
                memory, Redis, Redis Cluster
                memory only
              

            
          

        

      

      
* The memory store counts in sub-buckets of window ÷ 60, so a request can leave the window up to one sub-bucket early. The Redis stores keep an exact sorted set of timestamps instead. Numbers are from docs/benchmarks.md.

    

  


  

    

      

        Features
        
Built like infrastructure, not a snippet.

        
RateGate is a standalone service with a client SDK, not a library you wedge into each binary. That is what lets a fleet share one set of limits.

      

      

        

          

          
One check, your pick of transport

          
Every integration ends in the same atomic question: may this key proceed? Send it over REST or gRPC, or let the Go middleware ask on every request for you.

          
    
            
  • POST /v1/check returns the decision plus X-RateLimit-* headers
    • 
            
  • rategate.v1.RateGateService/CheckRateLimit over gRPC, with reflection
    • 
            
  • GinMiddleware and StdlibMiddleware for Go web services
    • 
            
  • client.NewHTTPClient and client.NewGRPCClient in the Go SDK
    • 
          

        

        

          

          
Pluggable storage, one contract

          
The memory store runs sharded, allocation-free limiters in-process. The Redis stores run the same algorithms as single-key Lua scripts, so a fleet of rate-limit servers shares one truth in one round trip per check.

          
    
            
  • Memory: about 48 B per token-bucket key, 960 B per sliding-window key
    • 
            
  • Redis and Redis Cluster: atomic Lua scripts and a TTL on every key
    • 
            
  • A janitor evicts idle keys (memory_sweep_idle, default 1h)
    • 
          

        

        

          

          
Demand-aware ceilings

          
The adaptive limiter raises its limit while demand grows and halves it when demand falls, always inside [floor, 4 × floor]. In-memory store only.

        

        

          

          
Fails the way you choose

          
Store errors deny by default. Set fail_open: true to trade safety for availability, or FailClosed on the middleware to do the reverse.

        

        

          

          
Observable by default

          
Prometheus metrics on /metrics, optional OpenTelemetry tracing, and structured slog output with request counters for allowed and denied checks.

        

        

          

          
Ships small

          
Static binaries for Linux and macOS on amd64 and arm64, a distroless non-root container, Kubernetes manifests, and about 12 MB of RSS at idle.

        

      

    

  


  

    

      

        Architecture
        
A request's path through RateGate.

        
A check is one atomic evaluation of one key against one policy. The core validates the policy, picks the store, and turns the store's answer into a decision with a reset time and, on denial, a retry hint.

      

      

        

          

            
1Clients

            
Your serviceGo SDK · Gin or net/http middleware

            
Anything elsecurl · grpcurl · any HTTP client

          

          

            
2Transport

            
REST · :8080POST /v1/check · /healthz · /metrics

            
gRPC · :9090CheckRateLimit · reflection

          

          

            
3Core

            
Authx-api-key, optional

            
Policy registrynamed policies · inline overrides

            
Fail open or closedwhen the store errors

          

          

            
4State

            
Memorysharded · idle sweeper

            
Redis / Redis Clusteratomic Lua scripts

          

        

        

          

            
Admin API

            
Policies at runtimePOST /v1/admin/policies · gRPC AdminService

          

          

            
Observability

            
Metrics, traces, logsPrometheus · OpenTelemetry · slog

          

          

            
Deploy

            
Binary · container · KubernetesLinux and macOS · distroless image

          

        

        
Named policies can be created, updated and deleted at runtime through the admin API. The change lands in the same registry the check path reads, so it applies to the next request on every transport without a restart. Runtime changes are not written back to the YAML file; a restart reseeds from it.

        Quickstart
        
Rate-limited in three commands.

        
No cluster, no sidecar, no configuration file needed for a first check. The container listens on both ports and starts with the in-memory store.

      

      

        

          
1

          

            
Start a server

            
A distroless image that runs as a non-root user, built for amd64 and arm64.

            

              
docker run --rm -p 8080:8080 -p 9090:9090 -e RATEGATE_STORE_BACKEND=memory ghcr.io/abolfazlrwm/rategate:latest

              
            

          

        

        

          
2

          

            
Send a check

            
The body carries the key and an inline policy. Change limit or refill_per_second and the decision follows.

            

              
curl -i -X POST localhost:8080/v1/check \
  -H 'Content-Type: application/json' \
  -d '{"key":"user:1","algorithm":"tokenbucket","limit":10,"refill_per_second":8}'

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 9
X-RateLimit-Reset: 1795430400

{"allowed":true,"remaining":9,"limit":10,"reset_at_unix_ms":1795430400125,"retry_after_ms":0,"algorithm":"tokenbucket"}

              
            

          

        

        

          
3

          

            
Guard a route

            
The middleware asks RateGate once per request and writes the same headers you saw above. A denied request never reaches your handler.

            

              
limiter := rategateclient.NewHTTPClient("http://localhost:8080")

r := gin.Default()
r.Use(rategatemw.GinMiddleware(limiter, rategatemw.Options{
    KeyFunc: func(req *http.Request) string { return "user:" + req.Header.Get("X-User-Id") },
    Algorithm: "tokenbucket",
    Limit:     10,
    Refill:    8, // 8 tokens per second, burst of 10
}))

              
            

          

        

      

    

  






  

    

      

        
          
          RateGate
        
        
A distributed rate limiter for Go, built in public under the Apache 2.0 license.

        
The playground is a static page. Its three algorithms are line-by-line JavaScript ports of internal/algorithms, replayed against the Go unit tests, and nothing you type here leaves your browser.
